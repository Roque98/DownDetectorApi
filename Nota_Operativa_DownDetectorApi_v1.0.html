🎯 Objetivo y Propósito

Esta nota operativa tiene como objetivo proporcionar al Centro de Operaciones una guía práctica y completa para el monitoreo efectivo del sistema DownDetector API. El documento está diseñado para que puedas comprender rápidamente qué es el sistema, cómo interpretarlo y qué acciones tomar ante diferentes situaciones operativas.

¿Para qué sirve esta herramienta?

  • Detección proactiva de interrupciones: Identifica problemas en servicios críticos de telecomunicaciones antes de que los usuarios finales escalen incidencias masivas.
  • Monitoreo automatizado 24/7: Recopila datos cada minuto desde DownDetector.com, proporcionando visibilidad continua del estado de servicios como Telegram, WhatsApp, Instagram y Facebook.
  • Clasificación inteligente de severidad: Calcula automáticamente el nivel de impacto con 5 niveles (0-2 OK, 3 Warning, 4 Alerta) comparando reportes actuales contra líneas base históricas.
  • Integración con PRTG: Visualiza métricas clave directamente en PRTG, facilitando la toma de decisiones durante el turno.

🔍 ¿Qué es DownDetector API?

DownDetector API es un sistema de monitoreo automatizado que funciona como un "termómetro digital" para servicios de telecomunicaciones críticos. Imagina que tienes un panel de control que te muestra en tiempo real cuántas personas están reportando problemas con servicios como Telegram o WhatsApp.

El sistema opera de forma autónoma: cada minuto consulta la plataforma DownDetector.com (un sitio web donde usuarios reportan fallas en servicios populares), extrae estadísticas de reportes, las compara contra valores normales y almacena todo en una base de datos SQL Server para enviarlos a PRTG. Lo interesante es que el sistema calcula automáticamente si la situación es normal o requiere atención, clasificándola en 5 niveles de severidad.

Conceptos Básicos que Debes Conocer

Concepto Definición Simple
ReportValue (Reportes) Número de usuarios que están reportando problemas con un servicio en este momento. Es como contar cuántas personas llaman a soporte simultáneamente.
BaseLineValue (Línea Base) Valor normal o esperado de reportes en condiciones normales. Es tu "referencia" para saber si algo está fuera de lo común.
Multiplicador Cuántas veces más reportes hay ahora comparado con lo normal. Ejemplo: si la línea base es 100 y hay 500 reportes, el multiplicador es 5x.
StatusCode (Código de Estado) Número del 0 al 4 que indica la severidad: 0-2 = OK, 3 = Warning, 4 = Alerta. Es como un semáforo con 5 niveles de granularidad.
Sensor PRTG Componente visual en PRTG que muestra gráficos con los datos del sistema.

Analogía práctica: Piensa en DownDetector API como un sistema de vigilancia de tráfico vehicular. La "Línea Base" es el tráfico normal a determinada hora. Los "Reportes" son el número actual de autos en la vía. Si hay 5 veces más autos de lo normal (multiplicador 5x), el sistema marca la situación como "Alerta" y te notifica que hay congestión.

📊 Clasificación de Estados del Sistema

El sistema clasifica automáticamente cada medición en cinco estados según el multiplicador (ratio entre reportes actuales y línea base de 1). Solo los StatusCode 3 y 4 generan alertas en PRTG.

✅ ESTADOS OK (StatusCode: 0, 1, 2)

¿Qué significa?
Estados normales de operación que NO requieren escalamiento. Multiplicador menor a 10x (menos de 10 reportes con línea base de 1). Se muestran en VERDE en PRTG.

¿Qué hacer?

  • StatusCode 0 (NORMAL): 0-1 reportes, multiplicador <2x. Ninguna acción requerida.
  • StatusCode 1 (NORMAL): 2-4 reportes, multiplicador 2x-5x. Monitoreo de rutina.
  • StatusCode 2 (NORMAL): 5-9 reportes, multiplicador 5x-10x. Observar tendencia, documentar si persiste.

Ejemplos:

  • Línea Base: 1 → Reportes: 1 → NORMAL
  • Línea Base: 1 → Reportes: 3 → NORMAL
  • Línea Base: 1 → Reportes: 8 → NORMAL

⚠️ WARNING (StatusCode: 3)

¿Qué significa?
Multiplicador 10x-20x. Entre 10 y 20 reportes simultáneos. Se muestra en AMARILLO en PRTG.

¿Qué hacer?

  • Verificar impacto interno: revisar si hay problemas de envío de mensajes Telegram, alertas Telegram encoladas, o respuestas no enviadas en bots Telegram
  • Notificar al supervisor de turno sobre la situación y el impacto identificado

Ejemplo: Línea Base: 1 → Reportes: 15 → WARNING

🚨 ALERTA (StatusCode: 4)

¿Qué significa?
Multiplicador ≥ 20x. Más de 20 reportes simultáneos. Se muestra en ROJO en PRTG. Situación crítica con problema real y significativo.

¿Qué hacer?

  • VERIFICACIÓN INMEDIATA: Revisar urgentemente problemas de envío de mensajes Telegram, alertas Telegram encoladas, y respuestas no enviadas en bots Telegram
  • ESCALAMIENTO INMEDIATO: Notificar al supervisor de turno

Ejemplo: Línea Base: 1 → Reportes: 25+ → ALERTA

📏 Criterios de Activación y Umbrales

El sistema utiliza fórmulas matemáticas automáticas para determinar el estado de cada servicio. Comprender estos criterios te ayuda a interpretar correctamente las alertas y a anticipar cambios de estado.

Fórmula de Cálculo del Multiplicador

Multiplicador = ReportValue / BaseLineValue Ejemplo práctico: - Reportes actuales (ReportValue): 8 - Línea base (BaseLineValue): 1 - Multiplicador = 8 / 1 = 8x - RESULTADO: Estado ALERTA (porque 8x está entre 5x y 10x)

Tabla de Umbrales Técnicos

StatusCode Estado Rango del Multiplicador Descripción Técnica
-1 SIN_BASELINE BaseLineValue = 0 No hay datos de referencia históricos. Situación excepcional que requiere investigación.
0 NORMAL Multiplicador < 2.0 Estado OK. Operación normal. Reportes dentro del rango esperado.
1 NORMAL 2.0 ≤ Multiplicador < 5.0 Estado OK. Incremento leve que requiere observación de rutina.
2 NORMAL 5.0 ≤ Multiplicador < 10.0 Estado OK. Incremento notable pero no crítico (línea base típica = 1).
3 WARNING 10.0 ≤ Multiplicador < 20.0 Estado WARNING. Advertencia de posible problema (10-20 reportes con línea base = 1).
4 ALERTA Multiplicador ≥ 20.0 Estado ALERTA. Situación crítica que requiere atención inmediata (20+ reportes).

Criterios de Validez de Datos

IMPORTANTE: Los sensores PRTG solo consideran datos válidos si no tienen más de 20 minutos de antigüedad. Este umbral se define así porque DownDetector tiene un delay natural de aproximadamente 15 minutos en la actualización de sus datos, por lo que esperar hasta 20 minutos garantiza que se capturen los datos más recientes disponibles. Si ves que un sensor muestra "No Data", significa que el proceso de recolección no ha actualizado datos recientemente y requiere investigación.

Indicadores de frescura de datos:

  • MinutosDesdeReporte: Muestra la antigüedad del último dato disponible
  • Datos Frescos: Última actualización hace menos de 20 minutos - Operación normal
  • Datos Obsoletos: Última actualización hace más de 20 minutos - Verificar estado del proceso de recolección

🖥️ Interfaz del Sensor PRTG

Canales que Visualizarás

Cada sensor PRTG muestra múltiples canales con las siguientes métricas:

Canal Qué Representa
Reportes Número actual de usuarios reportando problemas con el servicio. Indica la magnitud absoluta de reportes en este momento.
LineaBase Valor de referencia normal para el servicio. Regularmente este valor es 1, lo que significa que en condiciones normales hay 1 reporte base.
CodigoEstado Número del 0 al 4 que indica la severidad: 0-2 = OK (verde), 3 = Warning (amarillo), 4 = Alerta (rojo).
Multiplicador Cuántas veces más reportes hay ahora comparado con la línea base. Ejemplo: si hay 15 reportes y la línea base es 1, el multiplicador es 15x.
EnAlerta Indicador binario que activa notificaciones: 1 = el servicio está en WARNING o ALERTA (StatusCode 3 o 4), 0 = estados OK (StatusCode 0, 1 o 2).

🔄 Ciclo de Vida del Monitoreo

El sistema opera en un ciclo continuo automatizado. Comprender este flujo te ayuda a anticipar cuándo esperar datos actualizados y a detectar anomalías en el proceso.

Proceso de Recolección y Análisis

  1. Recolección Automática (cada 1 minuto): El sistema inicia un ciclo de recolección automática, consultando DownDetector.com para obtener información actualizada de estado de los servicios.
  2. Extracción de Datos: Se extraen los datos históricos de reportes de usuarios y valores de línea base desde DownDetector.
  3. Filtrado Temporal: Solo se procesan datos recientes (últimos 45 minutos) para evitar insertar información antigua o duplicada.
  4. Conversión de Zona Horaria: Las fechas se convierten automáticamente a hora local antes de almacenarse.
  5. Almacenamiento en Base de Datos: Los datos recolectados se guardan en la base de datos central del sistema.
  6. Cálculo Automático de Estado: El sistema calcula el multiplicador y asigna el StatusCode automáticamente según los umbrales definidos. Si el registro ya existe, no se duplica.
  7. Disponibilidad para PRTG: Una vez almacenados los datos, los sensores PRTG pueden visualizarlos. PRTG consulta según su intervalo configurado (recomendado: cada 5 minutos).
  8. Notificaciones Automáticas: Si ocurren errores críticos durante el proceso de recolección, el sistema envía alertas por Telegram al grupo de monitoreo.

Estados del Sistema de Recolección

Estado Descripción Qué esperar
Operación Normal El proceso está corriendo correctamente y actualizando datos cada 1 minuto Los sensores PRTG muestran datos frescos (menos de 20 minutos de antigüedad). No hay alertas de sistema.
Bloqueo de Origen DownDetector.com ha bloqueado temporalmente las consultas automatizadas Recibirás alerta de Telegram sobre el bloqueo. Los datos dejarán de actualizarse. El sistema reintenta automáticamente en el próximo ciclo.
Error de Base de Datos Falla de conexión o error en operaciones de base de datos Alerta de Telegram con detalles del error. Datos no se almacenan. Verificar conectividad con el servidor de base de datos.
Proceso Detenido El proceso de recolección no está corriendo (falla, reinicio, mantenimiento) Los sensores PRTG indicarán datos obsoletos después de 20 minutos. El sistema de monitoreo enviará alerta automática.

Frecuencia de Actualización

  • Proceso de recolección: Cada 1 minuto
  • Sensores PRTG: Intervalo recomendado de 1 minuto para visualizar datos en tiempo real
  • Monitoreo automático de servicios: Cada 15 minutos para detectar servicios inactivos
  • Depuración automática de datos: Elimina datos más antiguos de 4 días

✅ Beneficios del Sistema

Para el Equipo Operativo (Centro de Operaciones)

  • Detección proactiva de problemas: Identifica interrupciones en servicios críticos antes de que se conviertan en escalamientos masivos de usuarios. Te permite prepararte y comunicar anticipadamente.
  • Reducción de tiempo de respuesta: Elimina la necesidad de buscar manualmente en múltiples fuentes. Toda la información está centralizada en PRTG.
  • Clasificación automática de severidad: El sistema evalúa y clasifica automáticamente cada medición según los umbrales establecidos: 0-2 (OK/verde), 3 (Warning/amarillo), 4 (Alerta/rojo). La interpretación del estado es inmediata y estandarizada.
  • Visibilidad histórica: PRTG almacena el histórico de datos según su configuración de retención, permitiéndote revisar patrones de comportamiento, identificar incidencias recurrentes y generar análisis retrospectivos con cronología completa.

Para el Negocio

  • Mitigación de impacto reputacional: Al detectar y comunicar problemas rápidamente, reduces quejas de clientes y mejoras la percepción de proactividad del área de operaciones.
  • Toma de decisiones informada: Los líderes pueden evaluar el impacto real de interrupciones en servicios externos y decidir acciones (comunicados, contingencias, escalamientos comerciales).
  • Cumplimiento de SLAs: El registro histórico sirve como evidencia de detección temprana y tiempos de respuesta para auditorías y reportes de cumplimiento.

Para la Planificación

  • Análisis de tendencias: Los datos históricos permiten identificar patrones de interrupciones (días, horarios, servicios más problemáticos) para planificación de recursos.
  • Métricas de confiabilidad: Puedes calcular el uptime percibido de servicios externos críticos y su impacto en tus operaciones.
  • Justificación de inversiones: Datos cuantitativos sobre frecuencia e impacto de interrupciones ayudan a justificar inversiones en redundancia o servicios alternativos.

🛠️ Recomendaciones Operativas

Rutina Diaria Sugerida

Al Inicio del Turno

  1. Acceder al dashboard PRTG y verificar el estado de todos los sensores DownDetector configurados
  2. Revisar si hay sensores sin datos recientes o mostrando alertas de disponibilidad
  3. Consultar la bitácora del turno anterior para continuidad de incidencias abiertas relacionadas con servicios monitoreados
  4. Verificar que no haya alertas de Telegram sin atender sobre errores del sistema de recolección
  5. Registrar en bitácora: "Estado inicial de sensores DownDetector: [todos normales / X servicios en atención / problemas identificados]"

Durante el Turno

  1. Revisar el dashboard cada 30-60 minutos o cuando PRTG genere alertas
  2. Si un servicio permanece en NORMAL con variaciones: observar por 15-30 minutos y documentar en bitácora si es necesario
  3. Si un servicio alcanza ALERTA (StatusCode 4): ejecutar procedimientos de escalamiento inmediato (ver sección de Criterios de Escalamiento)
  4. Ante alertas de Telegram sobre errores del sistema de recolección: documentar en bitácora con timestamp. Si persiste más de 1 hora, notificar a equipo técnico responsable del sistema
  5. Correlacionar alertas de DownDetector con otros sistemas de monitoreo para confirmar o descartar impacto en infraestructura propia

Al Final del Turno

  1. Documentar en bitácora cualquier cambio de estado observado durante el turno con timestamps y acciones tomadas
  2. Verificar que no haya servicios en estado ALERTA sin escalamiento documentado
  3. Si hay incidencias en curso, realizar traspaso formal al siguiente turno incluyendo cronología de eventos
  4. Reportar al siguiente turno cualquier comportamiento anómalo del sistema (sensores sin datos recurrentes, alertas frecuentes del sistema de recolección)

Criterios de Escalamiento

Escalar inmediatamente cuando:

  • Cualquier servicio alcanza estado ALERTA (StatusCode = 4)
  • Los sensores PRTG muestran "No Data" por más de 30 minutos consecutivos (indica falla del sistema de recolección)

Escalar al Equipo de Infraestructura cuando:

  • Hay alertas recurrentes de Telegram sobre errores de base de datos (más de 3 en un turno)
  • El proceso de recolección está detenido (sensores sin datos por más de 30 minutos)
  • Bloqueos del sistema de recolección persisten por más de 2 horas consecutivas

Escalar al Equipo de Aplicaciones cuando:

  • Servicios críticos (Telegram, WhatsApp) alcanzan estado ALERTA, especialmente si se correlaciona con reportes de usuarios internos
  • Se requiere confirmación de impacto en operaciones que dependen del servicio afectado

Documentar para análisis posterior (sin escalamiento inmediato):

  • Variaciones normales del servicio que se mantienen en estado NORMAL
  • Fluctuaciones rápidas entre estados (posible ruido estadístico)
  • Patrones repetitivos en horarios específicos que puedan indicar comportamiento normal del servicio

📖 Glosario Técnico Simplificado

Término Definición
BaseLineValue (Línea Base) Valor de referencia que representa el comportamiento "normal" de reportes para un servicio en un momento específico. Es como el "pulso en reposo" de una persona: te dice qué esperar cuando todo está bien.
DownDetector.com Plataforma pública donde usuarios reportan problemas con servicios populares (redes sociales, mensajería, streaming, etc.). Es la fuente de datos para nuestro sistema.
Multiplicador Resultado de dividir los reportes actuales entre la línea base (ReportValue / BaseLineValue). Un multiplicador de 5x significa que hay 5 veces más reportes de lo normal.
PRTG Software de monitoreo de infraestructura usado en tu organización. Nuestro sistema se integra mediante "sensores SQL" que consultan la base de datos y muestran gráficos.
ReportValue (Reportes) Número de usuarios que están reportando problemas con un servicio en un momento específico. Es el indicador "en vivo" de cuánta gente está experimentando problemas.
Sensor PRTG Componente de PRTG que obtiene datos desde la base de datos y los convierte en gráficos monitoreables. Es el "puente" entre los datos almacenados y la interfaz de PRTG.
StatusCode (Código de Estado) Número del -1 al 4 que clasifica la severidad de la situación: -1 = Sin datos, 0-2 = Normal, 3 = Warning, 4 = Alerta.
